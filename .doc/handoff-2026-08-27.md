### 具体改动清单

#### A. 后端：数据库层（`server/internal/store/`）

**A1. `store.go` — 建表迁移**
- 新增 3 张表：`ai_models`、`model_prices`、`user_scenarios` + 5 个索引
- 新增幂等迁移辅助：`hasColumn` / `migrateAddColumn`（用 `pragma_table_info(?)` 检查列存在性后 `ALTER TABLE ADD COLUMN`）

- **v5 迁移**：`ai_models.cache_hit_rate INTEGER NOT NULL DEFAULT 0`

**A2. `ai_models.go` — 模型 CRUD**
- `AIModel` 结构体（json 字段与前端约定一致）：
  ```go
  type AIModel struct {
      ID int64 `json:"id"`
      Name string `json:"name"`              // 唯一
      Provider string `json:"provider"`
      BaseInputPrice float64 `json:"base_input_price"`       // 缓存未命中输入价
      BaseInputHitPrice float64 `json:"base_input_hit_price"` // 命中输入价（≤0 回退未命中价）
      BaseOutputPrice float64 `json:"base_output_price"`
      CacheHitRate int `json:"cache_hit_rate"` // 默认命中率 0-100
      Description string `json:"description"`
      ContextLength int `json:"context_length"`
      CreatedAt string `json:"created_at"`
      UpdatedAt string `json:"updated_at"`
  }
  ```
- `scanAIModel` 用 `sql.NullString`/`sql.NullInt64` 中转 NULL 列（**踩坑**：SQLite NULL 直接 Scan 到 string/int 报错）
- `ErrNameExists` 哨兵错误（handler 区分 409/500）
- `ListAIModelsWithPrices` **N+1 优化**：批量查询全部价格按 model_id 分组（查询次数恒定 2）
- 单位：¥/1M tokens（注释已同步）

**A3. `model_prices.go` — 价格配置 CRUD**
- `ModelPrice` 结构体：`InputHitPrice` / `InputMissPrice` / `OutputPrice` 三个绝对价格 + `TimeRange` + `IsActive`
- `boolInt(nil) → 1`（is_active 缺省激活；**注意**：is_favorite 语义不同，勿复用）

**A4. `user_scenarios.go` — 场景 CRUD**
- `UserScenario`：name/description/model_id/input_tokens/output_tokens/cache_hit_rate/is_favorite
- `favoriteValue(nil) → 0`（**踩坑**：is_favorite 缺省必须 0，boolInt 的 1 语义不适用）
- `cacheRateValue(nil) → 0`（NOT NULL 列防 NULL）

**A5. `price_calculator.go` — 计算核心（重点）**
- **价格语义（最终版）**：¥/1M tokens 绝对价格，三档维度（命中输入/未命中输入/输出）；`pricePerMillion = 1_000_000`
- 计算规则：
  1. 基础成本 = `hit×命中价/1M + miss×未命中价/1M + out×输出价/1M`
  2. 缓存节省 = `hit_tokens×(未命中价−命中价)/1M`（命中价≥未命中价时为 0）
  3. 峰值时段（默认 22:00-8:00，可自定义跨天）：优先 自定义价 > 峰值价 > 基础价；每档维度 0 回退基础价
  4. `CacheHitRate *float64` 可选：缺省用模型 `cache_hit_rate` 配置（v5）
- `CalculateMultiplePrices`：对比列表去重/跳过无效模型/按成本升序排名；`ModelComparison` 含 `Breakdown`/`CacheInfo`/`PeakInfo`（供前端多模型分项明细展示，v6）
- `priceBreakdown` 闭包 `calcTier` 处理维度回退

#### B. 后端：HTTP 层（`server/internal/tokencalc/` + `server/main.go`）

**B1. `handlers.go` — 全部 API 处理器**
- 模型：`HandleListModels` / `HandleCreateModel` / `HandleGetModel` / `HandleUpdateModel` / `HandleDeleteModel`
- 价格：`HandleListModelPrices` / `HandleCreateModelPrice` / `HandleUpdateModelPrice` / `HandleDeleteModelPrice`（子资源 `/api/models/{id}/prices/{priceId}`，跨模型访问 404）
- 计算：`HandleCalculatePrice`（POST /api/calculate-price，支持 `compare_model_ids`）
- 场景：`HandleListScenarios`（支持 `?model_id=` 过滤）/ `HandleCreateScenario` / `HandleGetScenario` / `HandleUpdateScenario` / `HandleDeleteScenario` / `HandleToggleScenarioFavorite`
- 校验模式：`httpx.DecodeJSON` / `httpx.WriteError` / `httpx.WriteJSON` / `httpx.ParseID`（与 todo 等模块一致）
- 输入校验：模型名称 ≤100 字、服务商 ≤50 字、价格非负、命中率 0-100、价格配置至少一个 >0

**B2. `main.go` — 路由注册（全部挂 `a.RequireAuth`）**
